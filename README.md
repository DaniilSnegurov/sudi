# Помощник для анализа документов из судов

Прототип для трека «Помощник для анализа документов из судов» хакатона «ИИ-ассистенты для энергетики».
Читает судебные приказы, исполнительные листы (PDF, в том числе сканы) и постановления ФССП (XML),
заполняет две таблицы по шаблонам заказчика и формирует отчёт о документах, которые должен проверить сотрудник.

Всё работает локально: тексты и изображения документов не покидают машину. Персональные данные
во внешние сервисы не передаются.

## Что умеет

- Принимает папку или ZIP; отдельные файлы можно загрузить через веб-интерфейс.
- Постановления ФССП: поля верхнего уровня XML, адрес по частям, суммы и период из текста предмета исполнения.
- Судебные PDF: тип документа, основной должник и его реквизиты, адрес, номер и дата дела, период, суммы, перечень должников.
- Значения хранят источник: блок текста на странице или путь в XML. Значение, которого нет в тексте документа, в таблицу не попадает.
- Сомнительные места не угадываются: ячейка остаётся пустой, документ попадает в отчёт с причиной и вариантами.
- Веб-интерфейс для сотрудника: список документов, страница с подсветкой источника поля, правка значений,
  отметка «проверен», выгрузка таблиц с учётом правок.

## Запуск

### Что нужно

| | |
|---|---|
| Видеокарта | NVIDIA; проверено на RTX 4070 с 12 ГБ (модель занимает около 6 ГБ при контексте 16 тыс. токенов) |
| Диск | около 12 ГБ: модель 6,6 ГБ, сервер моделей 2–4 ГБ, модели OCR 130 МБ |
| Интернет | только при первой установке: скачиваются модель и модели OCR. При работе не нужен |
| Без видеокарты | обрабатываются только XML ФССП (`--no-models`); судебные PDF помечаются как необработанные |

Видеопамять должна быть свободна. Если её занимает другая программа и модель не помещается целиком,
скорость падает в десятки раз (с десятков токенов в секунду до одного-двух).

### Вариант 1. Docker Compose

Нужны Docker и NVIDIA Container Toolkit (в Docker Desktop для Windows поддержка видеокарты уже есть).
Первый запуск скачивает образ сервера моделей (около 4 ГБ) и модель (6,6 ГБ).

```bash
docker compose up --build
```

Поднимаются три контейнера: `ollama` (сервер моделей на видеокарте), `model` (один раз скачивает `qwen3.5:9b`
и завершается) и `app` (OCR, правила, интерфейс). Интерфейс: http://localhost:8765.

Папка с документами монтируется в контейнер как `/app/courts_anonymized` — по умолчанию это `./courts_anonymized`,
другую задаёт переменная `COURTDOCS_INPUT`. Результаты и правки сотрудника лежат в томе `data`.

Пакетная обработка в том же контейнере:

```bash
docker compose run --rm app python -m courtdocs run courts_anonymized --out /data --labels courts_anonymized/labels
```

### Вариант 2. Локально (Windows или Linux)

1. Окружение Python 3.11 или новее и зависимости:

```bash
py -3.11 -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"
```

На Linux вместо `py -3.11` и `.venv/Scripts/python.exe` — `python3.11` и `.venv/bin/python`.

2. Сервер моделей [Ollama](https://github.com/ollama/ollama/releases) версии 0.35 или новее. Подойдёт обычная установка.
   Портативный вариант для Windows: распаковать `ollama-windows-amd64.zip` в `tools/ollama` и запускать через `start-models.ps1`
   (сервер слушает только `127.0.0.1:11434`).

```bash
powershell -File start-models.ps1
```

3. Модель — один раз, при запущенном сервере (при обычной установке Ollama — `ollama pull qwen3.5:9b`):

```bash
tools/ollama/ollama.exe pull qwen3.5:9b
```

4. Веб-интерфейс. Запускать из корня проекта; откроется на http://localhost:8765:

```bash
.venv/Scripts/python.exe -m uvicorn courtdocs.web:app --port 8765
```

5. Либо пакетная обработка с сравнением с эталоном:

```bash
.venv/Scripts/python.exe -m courtdocs run courts_anonymized --out out --labels courts_anonymized/labels
```

Учебный набор организаторов в репозиторий не входит. Его нужно распаковать в `courts_anonymized/` в корне проекта так,
чтобы внутри лежали `ocr/`, `fssp/`, `labels/` — как в `manifest.json` набора.

### Что получается

В папке результата (`out/`): `judicial.xlsx`, `fssp.xlsx`, `issues.xlsx`, те же таблицы в CSV и `result.json` — каждое
поле с источником, способом получения и замечаниями. В `out/cache/` — распознанный текст и ответы модели: повторный
запуск на тех же файлах занимает секунды.

### Параметры

| Переменная или ключ | Значение по умолчанию | Что задаёт |
|---|---|---|
| `COURTDOCS_LLM_URL`, `--model-url` | `http://127.0.0.1:11434` | адрес сервера моделей |
| `COURTDOCS_LLM_MODEL`, `--model` | `qwen3.5:9b` | языковая модель |
| `COURTDOCS_VLM_MODEL`, `--vlm-model` | та же | модель со зрением |
| `COURTDOCS_WORKDIR` | `out` | рабочая папка веб-интерфейса |
| `--no-models` | | только XML, без OCR и моделей |
| `--no-vlm` | | без перечитывания по изображению |
| `--only ПАПКА` | | обработать часть пакета |
| `--mode fused` | `text` | опытный режим: модель со зрением читает страницу вместе с текстом OCR |

Модели, порог уверенности OCR и перечитывание по изображению меняются и в интерфейсе, на вкладке «Настройки».

### Тесты

```bash
.venv/Scripts/python.exe -m pytest -q
```

Тесты на учебном наборе пропускаются, если нет папки `courts_anonymized/`; тесты судебных PDF на моделях — если не
запущен сервер моделей. Остальные работают на подставных OCR и моделях и ничего не требуют.

## Архитектура

```
PDF ─► OCR (блоки с координатами и оценкой) ─► языковая модель (факты, дословно из текста)
                                                 │
                         правила (суммы, период, состав должников) ─► сверка
                                                 │
            проблемные места ─► модель со зрением перечитывает фрагмент изображения (без подсказки)
                                                 │
                              выбор полей по правилам ─► таблицы и отчёт
XML ─► поля верхнего уровня ─► правила для текста и адреса ─► таблицы и отчёт
```

### Маршруты

- **XML ФССП — без моделей.** Поля берутся только из непосредственных дочерних элементов корня. Суммы и период
  из `IdDebtText` извлекают правила. Парный PDF подтверждает пару по идентификатору постановления и отдельной строки не даёт.
- **Судебный PDF.** Каждая страница распознаётся OCR. Языковая модель получает текст и отвечает на три-четыре узких
  запроса: реквизиты дела, участники, суммы, карточка должника. Она копирует значения дословно; место в документе находит код.
  Правила независимо читают суммы, период и ФИО с датами рождения и сверяются с моделью.
- **Перечитывание по изображению.** Фрагмент страницы уходит модели со зрением, если значение не прошло проверку формата,
  распознано с низкой оценкой или трактуется по-разному. Кандидат OCR ей не сообщается. Совпало — принято; OCR дал
  непригодное значение — принято чтение по изображению с пометкой; прочитано по-разному — ячейка пустая, оба варианта в отчёте.
  Проход один, повторных циклов нет.
- **Основной должник.** Карточка «Должником по исполнительному документу является»; на бумажном листе — рукописная
  отметка у записи должника (три кадра, решение только при единогласии); иначе первый по порядку.

### Компоненты

| Модуль | Назначение |
|---|---|
| `registry.py` | регистрация пакета: безопасная распаковка ZIP, контрольные суммы, копии, пары XML/PDF |
| `pipeline.py` | обход пакета; сбой одного файла не останавливает остальные |
| `fssp_xml.py`, `address.py`, `debt_text.py` | маршрут XML: поля, адрес, суммы и период по правилам |
| `ocr.py` | рендер страниц, OCR, порядок чтения с учётом наклона скана, кэш |
| `llm.py` | адаптер моделей: ответ по JSON-схеме, ограниченные повторы, журнал вызовов |
| `facts.py` | запросы к модели и схемы ответов |
| `judicial.py` | кандидаты с источниками, проверки, задания на перечитывание, выбор полей |
| `names.py`, `parse.py` | именительный падеж ФИО; даты, суммы, номера |
| `export.py`, `evaluate.py` | таблицы по шаблонам, отчёт, сравнение с эталоном |
| `web.py`, `static/index.html` | интерфейс сотрудника и его API |
| `cli.py` | командная строка |

### Модели

- **OCR** — PP-OCRv5: детектор server, распознавание для русского; исполняется через ONNX на процессоре, около 5 с на страницу.
- **Языковая модель и модель со зрением** — `qwen3.5:9b` через локальный Ollama, одна на обе роли.
  У модели нет инструментов; ответ ограничен JSON-схемой и проверяется кодом; содержимое документа передаётся как данные.
- Версии OCR, запросов и моделей записываются в результат каждого документа.

### Данные и безопасность

- Обработка локальная; сервер моделей и интерфейс слушают только `127.0.0.1`.
- XML читается без внешних сущностей; ZIP распаковывается только внутрь рабочей папки и с ограничением объёма;
  имена загруженных файлов очищаются от путей.
- Правки сотрудника хранятся отдельно от автоматического результата (`out/web/store.json`) и не затираются повторной обработкой.

### Отличия от спецификации

Правила выбора каждого поля описаны в [architecture-spec.md](architecture-spec.md) (версия 1.0, написана до реализации).
Реализация отличается в следующем:

- модели работают локально через Ollama, а не через внешнего провайдера;
- модель получает не один большой запрос, а несколько узких, и не указывает блоки-источники — их находит код;
- суммы, период и состав должников дополнительно читают правила; текст `IdDebtText` в XML разбирают только правила;
- модель со зрением ещё и ищет рукописную отметку основного должника;
- текстовый слой PDF как дополнительный источник не используется.

## Результат на учебном наборе

Открытый обезличенный набор организаторов: 23 судебных PDF и 21 XML ФССП.

| | Совпадение ячеек с эталоном | Расхождений |
|---|---|---|
| Постановления ФССП (21 XML) | 97,3 % | 13 |
| Судебные документы (23 PDF) | 96,7 % | 16 |

Почти все расхождения — случаи, где система следует документу, а не эталону (например, ИНН есть в карточке должника,
а в эталоне пусто), либо документ отправлен на проверку. Реестр расхождений с причинами — в
[tests/test_fssp_dataset.py](tests/test_fssp_dataset.py) и [tests/test_judicial_dataset.py](tests/test_judicial_dataset.py).

Из 44 документов 34 проходят без замечаний, 10 уходят на проверку, необработанных нет. Модель со зрением исправила
три значения, повреждённых OCR («4об0 руб.» → 4000; «0 538» → 10 538; паспорт «8966 б08781» → 8966 608781).

Правила и кадрирование настраивались на этих же документах, отложенной выборки нет — на новых документах качество
будет ниже. Время: около 20–25 с на одностраничный PDF, XML — доли секунды.

## Ограничения и что дальше

- Вторая задача трека — отбор актов арбитражных судов по ключевым формулировкам и письмо юристу — не реализована:
  нет перечня формулировок и примеров документов.
- Порог уверенности OCR не откалиброван; ошибку распознавания с правдоподобным форматом система не заметит.
- Поиск рукописной отметки основного должника ненадёжен на листах с посторонними штрихами — такие документы уходят на проверку.
- Нет мониторинга качества во времени; интерфейс рассчитан на одного пользователя.
